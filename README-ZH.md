# RustClipSync Mobile

独立 Android（Kotlin / Jetpack Compose）与 iOS（Swift / SwiftUI）客户端，
共用 Rust mobile facade 和 [rustclipsync-core](https://github.com/Infinifar/rustclipsync-core)。
现有小企鹅输入法维持 Kotlin，本仓库不迁移其实现。
Apple 客户端只面向 iPhone / iPad；macOS 客户端之后在桌面端仓库考虑。

已建立 Cargo workspace、UniFFI 双端绑定、串行会话与主动关闭，并接入两端原生源码。
Rust core 49 项、facade 12 项合成测试通过；Android 已在私有 GitLab 完成应用 / 测试 APK
编译、lint、16 KiB 静态对齐。Android 12 / API 31 与 Android 15 / API 35 各通过 10 项
smoke，真实隔离服务覆盖发送 / 接收、敏感三策略、断网与重启恢复、后台通知及写入，
两端均验证实际通知栏显示 / 隐藏 / 复制，API 35 另验证系统超时关闭。完整服务方法分别为 5 / 6 项，未完成探测单列。剪贴板为模拟适配器，状态使用
独立合成 key / 文件；通知和前台服务使用真实模拟器框架。iOS 平台编译与真机、真实
剪贴板 / Keystore 验证尚未完成。详细证据见 [验证记录](docs/VALIDATION.md)。

| 层 | 职责 |
| --- | --- |
| Android 12+ / Compose | 界面、系统剪贴板、Keystore、权限与生命周期 |
| iOS 18+ / SwiftUI | 界面、系统剪贴板、Keychain、权限与生命周期 |
| 同一 Rust facade | UniFFI 接口、串行执行线程、错误映射、幂等关闭 |
| core 0.3.0 | 协议、同步状态机、RCS1 格式、重试、确认与冲突 |

core 固定到 Git 提交 `1a8ec6b97cc925fcbbbf51f9b8c8e31f97f1ea4e`，Cargo.lock 固定传递依赖，
通过 Cargo source replacement 使用同提交的带校验 vendor，不依赖相邻目录。
当前 HTTP 接口统一为 `/api/...`，需要配套服务端；服务器配置填部署根地址（可含子路径），
不额外附加 `/api` 或 `/v1`。端点全部由 core 维护。
首版为前台手动发送/接收；敏感默认跳过，另有加密收件箱和显式自动写入。
未标记文本无法保证识别为敏感内容。账户密码仅保存在会话内存；后台监听默认关闭，未启用时离开前台关闭会话。

## 可选后台监听、写入与加密收件箱通知

Android 提供两个独立开关，默认都关闭：**后台监听**保留当前会话，使用前台服务
约每 30 秒检查服务器；**允许后台自动写入剪贴板**需单独确认，决定后台是否把普通消息
写入系统剪贴板。后台不读取剪贴板，不能比较其他应用刚复制的内容，因此启用写入
可能覆盖该内容。关闭写入时，普通消息不消费，留待回到前台处理；服务端仍只保留最新消息。

已标记敏感内容始终遵循所选策略：跳过、加密收件箱、显式自动写入。后台写入开关
不会绕过此策略；自动写入敏感消息需要同时启用敏感自动写入和后台写入。加密收件箱
仍只保存最新一项，沿用 core 的 RCS1 加密持久化与 `skipped` 确认，不假称剪贴板已写入。
未标记文本不能承诺自动识别为敏感内容。

当 **加密收件箱启用、后台监听服务运行、系统通知及收件箱频道获准，且收件箱有消息**
时，显示“加密收件箱”通知。重新连接会恢复磁盘中已有消息的通知；回到应用只隐藏正文，
保留操作卡片，不必等待另一条新消息。应用内“显示收件箱通知”可重新发布被划掉的卡片。正文默认显示 `**`，展开后下方
有两个相邻的系统文本操作：**显示**与**复制**。显示正文后，第一个按钮变成**隐藏**，
再次点击恢复 `**`，共两种状态。预览最多显示 2,000 个字符，复制使用完整正文。
复制在后台显式完成，保留敏感标记，不需要开启后台自动写入。

显示与复制要求设备解锁；锁屏公开预览始终为 `**`。新消息、熄屏、回到前台均隐藏正文；停用
收件箱策略、停止监听或关闭会话移除通知；旧消息的按钮不能操作新消息。正文
和凭据不进入 Intent、日志或普通状态事件。显式显示后，通知正文会交给系统展示；
收件箱文件仍加密，通知预览不是端到端加密。拒绝通知不影响收件箱保存。

Android 15+ 的 `dataSync` 前台服务受系统后台运行时限约束，目前为每 24 小时共 6 小时，
回到前台会重置计时；到时立即停止服务并关闭后台会话。系统也可能延迟网络或终止进程，
不承诺常驻或实时。停止、划掉任务、重启后不自动连接，不保存账户密码。iOS 当前保持
前台会话，**后续通过推送等配套能力支持后台接收**，不添加无法兑现的常驻监听开关。

实现与官方依据见 [后台接收说明](docs/BACKGROUND.md)。各次编译与运行结果记录在
[验证记录](docs/VALIDATION.md)；早期失败探测单独保留，不计入最终通过数量。

通知栏只有“后台监听”时，请查看应用中的收件箱状态：空收件箱、未选择加密收件箱策略、
权限 / 频道关闭会分别提示。普通未标记文本不会自动进入敏感收件箱。系统折叠通知时
会隐藏原生操作按钮，点“加密收件箱”右侧展开箭头后，可见并排的“显示 / 隐藏”和“复制”。
应用顶部显示版本与构建号；本轮为 0.1.1，避免把旧包误认为包含当前修复。

实际通知栏截图：[默认隐藏与两个按钮](docs/evidence/android-notification-ui-2026-11-01/api35-hidden.png)、
[显示正文后变为“隐藏”](docs/evidence/android-notification-ui-2026-11-01/api35-shown.png)。

## Android 0.1.2：界面与通知交互

界面分为“同步、收件箱、设置”：同步页集中连接、收发与状态；收件箱页集中敏感消息及
通知入口；设置页集中外观、敏感策略、后台接收和版本信息。支持跟随系统、浅色、深色
三种主题，保存选择，使用 Android 12+ Material You 配色；内容按窗口宽度收缩并支持滚动，
适用于折叠屏的窄窗口。密码只保留在内存，不写入界面恢复 Bundle。

通知采用独立透明单色剪贴板图标。解锁状态下显示／隐藏由服务直接处理，不请求系统认证
流程，目标为保持通知栏展开；复制保留认证路径以收起通知栏。锁屏时显示请求被服务拒绝，
需先解锁后操作，公开预览始终为 `**`。

用户设备为 moto razr 60 u、Android 16 / MyUI。该系统的通知栏行为与界面视觉验收交给
用户完成；本轮不启动模拟器、截图或耗时可视化测试，编译与 lint 结果另见验证记录。

## Android 0.1.3：同步规则与语言

- 同步方向对齐桌面端：双向、仅发送、仅接收。设置作用于当前会话，Rust facade 在串行执行线程内再次检查方向；仅发送不消费远端消息，且停止后台接收。仅接收通过 core 撤销旧发送候选，重试入口只完成撤销／确认，不重发旧上传；已提交的请求不能撤回。
- 文本正则过滤：关闭／黑名单／白名单，每行一条，最多 32 条、每条 512 UTF-8 字节，可同时过滤接收。规则编辑和非敏感样例测试在独立“过滤”页，完全复用 core 的 Rust 正则语义，不使用 Kotlin／Swift 正则重写；保存变化时通过 core 清除旧本地发送候选。已接收的历史收件项不重放或自动删除。
- 同步状态显示可选中的真实设备 UUID 和游标；UUID 来自 core 的加密持久化身份，不生成另一套平台设备 ID。
- 隐藏正文使用不依赖秘密长度的多颗星号，按当前显示宽度和字体计算约占通知宽度 2/3；原生通知内边距随系统变化，MyUI 最终视觉效果由用户验收。已删除“展开可显示／隐藏、复制”副标题，折叠／旋转后重新计算占位。
- 设置分为“同步、过滤、外观、关于”。外观中支持跟随系统、简体中文、English；界面、状态／错误、通知按钮均使用资源翻译，Android 13+ 接入系统应用语言，Android 12 使用保存的应用语言设置。
- 关于页有检查更新、发布页和项目地址。检查只读取 GitHub 的公开 Release 元数据，不发送同步账户凭据，不自动下载或安装。当前仓库为私有且无正式 Release，404 会提示登录发布页核对，不宣称“已是最新版”；开发构建不等同正式发布。

新增语言：添加 `values-<语言标签>/strings.xml` 的完整翻译，登记 `AppLanguage` 和
`res/xml/locales_config.xml`，运行 `python3 scripts/check-translations.py` 检查键与格式占位符一致。
默认英文资源作为回退，规则／样例和服务端正文不会被翻译。视觉和真机测试继续交由用户。
