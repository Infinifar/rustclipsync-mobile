# RustClipSync Mobile

独立 Android（Kotlin / Jetpack Compose）与 iOS（Swift / SwiftUI）客户端，
共用 Rust mobile facade 和 [rustclipsync-core](https://github.com/Infinifar/rustclipsync-core)。
现有小企鹅输入法维持 Kotlin，本仓库不迁移其实现。
Apple 客户端只面向 iPhone / iPad；macOS 客户端之后在桌面端仓库考虑。

已建立 Cargo workspace、UniFFI 双端绑定、串行会话与主动关闭，并接入两端原生源码。
Rust core 49 项、facade 12 项合成测试通过；Android 在私有 GitLab 完成应用 / 测试 APK
编译、lint、16 KiB 静态对齐。Android 12 / API 31 与 Android 15 / API 35 各通过 9 项
smoke，真实隔离服务分别通过 4 / 5 项完整场景，涵盖发送 / 接收、敏感三策略、断网与
重启恢复、后台通知及写入，API 35 另验证系统超时关闭。剪贴板为模拟适配器，状态使用
独立合成 key / 文件；通知和前台服务使用真实模拟器框架。iOS 平台编译与真机、真实
剪贴板 / Keystore 验证尚未完成。详细证据见 [验证记录](docs/VALIDATION.md)。

| 层 | 职责 |
| --- | --- |
| Android 12+ / Compose | 界面、系统剪贴板、Keystore、权限与生命周期 |
| iOS 18+ / SwiftUI | 界面、系统剪贴板、Keychain、权限与生命周期 |
| 同一 Rust facade | UniFFI 接口、串行执行线程、错误映射、幂等关闭 |
| core 0.3.0 | 协议、同步状态机、RCS1 格式、重试、确认与冲突 |

core 固定到 Git 提交 `1a8ec6b97cc925fcbbbf51f9b8c8e31f97f1ea4e`，Cargo.lock 固定传递依赖，
通过 Cargo source replacement 使用同提交的带校验 vendor，不依赖相邻目录。
当前 HTTP 接口统一为 `/api/...`，需要配套服务端；服务器配置填部署根地址（可含子路径），
不额外附加 `/api` 或 `/v1`。端点全部由 core 维护。
首版为前台手动发送/接收；敏感默认跳过，另有加密收件箱和显式自动写入。
未标记文本无法保证识别为敏感内容。账户密码仅保存在会话内存；后台监听默认关闭，未启用时离开前台关闭会话。

```sh
scripts/check.sh
```

运行需要 Rustup、C 编译器、Git、Python 3 和 OpenSSL（隔离 HTTPS 测试）。Android 按要求使用 GitLab 开发构建；
iOS 需要 macOS / Xcode，Linux 不提供 iOS 编译验证。

## 可选后台监听、写入与加密收件箱通知

Android 提供两个独立开关，默认都关闭：**后台监听**保留当前会话，使用前台服务
约每 30 秒检查服务器；**允许后台自动写入剪贴板**需单独确认，决定后台是否把普通消息
写入系统剪贴板。后台不读取剪贴板，不能比较其他应用刚复制的内容，因此启用写入
可能覆盖该内容。关闭写入时，普通消息不消费，留待回到前台处理；服务端仍只保留最新消息。

已标记敏感内容始终遵循所选策略：跳过、加密收件箱、显式自动写入。后台写入开关
不会绕过此策略；自动写入敏感消息需要同时启用敏感自动写入和后台写入。加密收件箱
仍只保存最新一项，沿用 core 的 RCS1 加密持久化与 `skipped` 确认，不假称剪贴板已写入。
未标记文本不能承诺自动识别为敏感内容。

仅当 **加密收件箱启用、后台监听服务运行、应用处于后台、系统通知及收件箱频道获准，
并且收到新的收件箱消息** 时，发布“加密收件箱”通知。正文默认显示 `**`，展开后下方
有两个相邻的系统文本操作：**显示**与**复制**。显示正文后，第一个按钮变成**隐藏**，
再次点击恢复 `**`，共两种状态。预览最多显示 2,000 个字符，复制使用完整正文。
复制在后台显式完成，保留敏感标记，不需要开启后台自动写入。

显示与复制要求设备解锁；锁屏公开预览始终为 `**`。新消息、熄屏、回到前台、停用
收件箱策略、停止监听或关闭会话均撤销正文预览；旧消息的按钮不能操作新消息。正文
和凭据不进入 Intent、日志或普通状态事件。显式显示后，通知正文会交给系统展示；
收件箱文件仍加密，通知预览不是端到端加密。拒绝通知不影响收件箱保存。

Android 15+ 的 `dataSync` 前台服务受系统后台运行时限约束，目前为每 24 小时共 6 小时，
回到前台会重置计时；到时立即停止服务并关闭后台会话。系统也可能延迟网络或终止进程，
不承诺常驻或实时。停止、划掉任务、重启后不自动连接，不保存账户密码。iOS 当前保持
前台会话，**后续通过推送等配套能力支持后台接收**，不添加无法兑现的常驻监听开关。

实现与官方依据见 [后台接收说明](docs/BACKGROUND.md)。本功能的最终编译与运行结果记录在
[验证记录](docs/VALIDATION.md)，对应 GitLab #125 / job #284；早期失败探测单独保留，不计入通过数量。
