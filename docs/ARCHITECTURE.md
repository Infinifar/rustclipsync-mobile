# 移动端架构

状态：共享 facade、双端原生源码已建立；Rust / host FFI 与 Android APK 编译、lint、
16 KiB 静态对齐已通过。iOS 编译、真机与服务互操作待验证。
实现契约见 [BINDINGS.md](BINDINGS.md)，构建见 [BUILD.md](BUILD.md)，结果见 [VALIDATION.md](VALIDATION.md)。

本仓库的产品范围仅为 Android 与 iOS / iPadOS 移动端，不增加 macOS 或 Mac Catalyst
应用目标。macOS 客户端之后在桌面端仓库考虑。文档中的 macOS / Xcode 指 iOS 构建宿主。

## 三层职责

```text
Kotlin / Compose UI                 Swift / SwiftUI UI
        │                                  │
Android 平台适配与桥接               iOS 平台适配与桥接
        └────────────────┬─────────────────┘
                 同一 Rust mobile facade
                         │
                  rustclipsync-core
```

平台层处理系统剪贴板、敏感提示、密钥存储、权限、原生 UI 和前后台生命周期。
Keystore / Keychain 的具体密钥封装方式由平台实现，向 facade 提供必要的适配能力。
不把配对凭据或状态密钥作为普通设置明文保存。

facade 提供两端共用的移动端命令、结果、事件与错误类型，转换为 core 的接口。
它持有同步会话，串行调度会话操作，管理线程、取消、关闭和绑定资源。
平台差异通过适配接口表达，不分别维护两个同步引擎。

core 继续负责 HTTPS 协议、状态机、outbox、游标、确认、重试、冲突和 RCS1
加密持久化格式。core 通过 Clipboard、StateStore、HistorySink 等边界使用适配器；
文件落盘、权限、密钥保管及系统剪贴板调用本身不由 core 实现。
当前 core 0.3.0 统一访问 `/api/...`；HTTP 路由只在上游 core 修改后更新快照，
平台与 facade 不追加版本前缀，也不实现 `/v1` 探测或回退。服务器配置表示部署根地址。

## 当前目录

```text
android/                         # Kotlin / Compose 应用与 Android 桥接
ios/                             # Swift / SwiftUI 应用与 iOS 桥接
crates/rustclipsync-mobile-ffi/   # 两端共享的 Rust facade
docs/                            # 架构、决策与构建 / 验证记录
```

facade 作为独立 crate，避免给 core 加入 Android、iOS 或 UI 依赖。
已采用 UniFFI 0.32.2，实际生成双端绑定；评估及 Kotlin close 名称冲突处理见 BINDINGS.md。
不因会话持有状态就直接认定必须手写 JNI。剪贴板文本默认采用简单、可验证的数据传输；
只有测量证明必要时才引入 direct buffer 或零拷贝设计。

## 并发与生命周期

- 同一 Session 的命令串行执行，由一个明确的执行者持有；UI 不直接读写其内部状态。
- UI 主线程不执行 core 的阻塞网络操作或 Worker::join()。
- 平台剪贴板调用可能需要线程切换；不得形成“UI 等待 Rust，而 Rust 等待 UI”的环。
  具体调用、快照校验、写入完成与确认时序必须在绑定设计中写清楚。
- close / shutdown 要有明确状态、重复调用规则和在途请求处理方式。
  关闭后不向已销毁的界面派发回调，绑定对象的销毁不替代主动关闭。
- Worker 的 shutdown 请求与 join 等待分开安排。自定义 Transport 的整个操作
  包括长轮询必须有有限超时；核心当前内置请求超时为 30 秒。
- 核对 Android / iOS 的前后台能力和用户可见行为；不承诺两端都能任意常驻读取剪贴板。

## 持久化与兼容性

- 固定 core 依赖来源，记录提交、版本和更新方式，确保新 clone 可独立构建。
- 沿用 core 的事务与加密格式，不在 facade 定义另一个同步状态文件格式。
- StateStore 提交必须满足原子替换和故障恢复约定；存储或密钥错误不得被当成首次安装。
- 保留消息 ID、敏感标记、游标与原有客户端的协议语义；不要为移动 UI 修改协议行为。
- 需要修改 core 时，在 core 仓库单独实现并验证，再更新这里固定的依赖。

## 敏感内容契约

| 接收策略 | 新的已标记敏感消息 |
| --- | --- |
| 不允许敏感同步 | 跳过，不写系统剪贴板，不进入敏感收件箱 |
| 允许敏感同步，关闭自动写入 | 保存到加密收件箱，不改变系统剪贴板 |
| 允许敏感同步，显式启用自动写入 | 实际写入成功后确认，并保留平台支持的敏感提示 |

收件箱手动复制属于显式操作。普通状态事件只返回元数据；显示正文需单独读取。
切换策略不会重放已消费消息。平台剪贴板适配器只有在系统实际接受写入后才能报告成功，
不能把“已放入私有收件箱”当作成功写入系统剪贴板。

2026-11-01 的桌面排查确认：omawarden 提供敏感标记，而所检查的 Bitwarden
Chromium 扩展 2026.10.0 使用普通文本复制接口。未标记的密码 / TOTP 可能按普通文本同步。
这是来源覆盖限制，不可承诺“密码管理器复制一定会被识别”。接收端剪贴板历史列表和当前
可粘贴内容也应分开解释；平台敏感提示不是阻止其他应用读取当前剪贴板的安全边界。

## 错误与验证

facade 使用明确的错误种类映射 core 错误，Rust 内部保留原因链，绑定层提供可行动的信息。
不把 URL 中的凭据、令牌、剪贴板正文或底层错误的敏感输入直接交给 UI 和日志。
FFI 的 panic 隔离必须结合 unwind / abort 的实际构建策略验证，不能承诺 catch_unwind
可以捕获 abort。

验收先覆盖核心适配契约、序列化执行、关闭、存储失败、敏感策略与互操作，再补平台测试。
Android 的打包 / ABI / 页大小要求及 iOS 的签名 / 生命周期能力，在实施时查证并记录。
协议测试、绑定生成、平台编译和真机行为是不同层级的证据，逐项报告。
